# Polyglass — Development Checklist

> Living tracker for implementation work. Companion to [`SPEC.md`](./SPEC.md) (requirements) and [`PLAN.md`](./PLAN.md) (architecture/roadmap).
> **Every session:** read "Current state" and the latest "Session log" entry first, pick tasks, mark them `[~]`, and add a log entry before you finish.

## How to use this file

| Mark | Meaning |
|---|---|
| `[ ]` | Not started |
| `[~]` | In progress / partially done (see note) |
| `[x]` | Done and verified (tests pass or reviewer checked) |
| `[!]` | Blocked (reason in note) |
| `[-]` | Dropped / deferred past v1 (reason in note) |

- Task IDs are `M<milestone>-<area>-<n>` and never reused. Requirement IDs (e.g. `CAP-03`) point into SPEC.md.
- A task is `[x]` only when its acceptance check is automated (test name given) or noted as manually verified.
- Keep tasks small enough for one session. Split a task instead of leaving it `[~]` for several sessions.
- Commands every session should keep green:
  ```
  cargo fmt --all -- --check
  cargo clippy --workspace --all-targets -- -D warnings
  cargo test --workspace
  ```

## Post-v1 platforms (macOS, Linux)

v1 is Windows only (D-15, 2026-11-03). What the D-15 cleanup removed, and what to know when a platform comes back:

- **Where a platform plugs in** (`docs/ARCHITECTURE.md`, "Adding a platform"): a `ScreenCapturer` in `pg-capture` and an `OcrEngine` in `pg-ocr` behind `#[cfg]`; the app's Windows-only parts (`lens.rs` capture exclusion, `hold.rs` key state, `live.rs` pipeline, `commands.rs` OCR settings, `crash.rs` folder opener, the `LOCALAPPDATA` model-store path in `pg-bench` and `import-models`, the system fonts in `pg-testkit`) each have a `cfg(windows)` branch to add to. Non-Windows builds still compile in principle (demo mode), but nothing checks that any more.
- **Removed in the D-15 cleanup** (restore from git history, the commit after `46eb12f`): CI's Linux/macOS `test` matrix and Linux packages, `measure.yml`'s Linux/macOS jobs, the OCR-01 per-platform table (`pg_ocr::default_engine`, `Platform`, `EngineKind`), Tauri's `macos-private-api` feature and `macOSPrivateApi` (needed for transparent windows on macOS, PLAN §5), `icons/icon.icns`, the macOS ⌘⌥ hotkey modifiers, the macOS/XDG data-dir and font paths, RSS through `/proc` and `ps` in `real_models.rs`, `deny.toml`'s RUSTSEC-2024-0370 ignore (`proc-macro-error`, Tauri's Linux GTK 3 stack) and its unused licenses.
- **Linux build:** CTranslate2's runtime CPU dispatch doesn't link with GCC 15.2 on Ubuntu 26.04 (it targets x86-64-v3 by default). The fix was `ct2rs` feature `disable-cpu-dispatch` for `cfg(target_os = "linux")` in `crates/pg-ct2/Cargo.toml` (ADR-0005 "Build"); for release builds also set a CPU baseline (e.g. `-march=x86-64-v2`), or the build needs an AVX2 CPU.
- **macOS:** CTranslate2 builds and runs on Apple silicon (`Measure`, 2026-11-02); `accelerate` may be faster than ruy (untested). Intel Macs are out (D-11): ruy's x86 SIMD kernels are off with Apple clang, ≈ 35–50× slower (`RUY_FORCE_ENABLE_X86_ENHANCEMENTS` or Accelerate if Intel ever comes back). The hold-Option key (REN-04) has no source and the ⌘⌥ hotkeys were never tried.
- **Open from the `Measure` runs:** the model conversion reported "FAILED or differs from the Windows pins" on Linux and macOS (step log never seen), so the models release is only known to be reproducible on Windows. Linux had one eval segment at 6974 ms (likely a runner stall); chrF differs a little per OS (sv-en Linux 75.18, macOS 76.66, Windows 76.45, pre-D-10 guard).
- **Hardware:** the interactive parts (transparency, click-through, Screen Recording permission, X11 flicker, latency) need a real Mac and a Linux desktop. From a Windows machine, Linux can be developed in WSL2 (build, tests) plus a Hyper-V Ubuntu VM with an Xorg session (overlay, X11 capture); macOS code can be built and tested on GitHub's macOS runners, but a macOS VM on non-Apple hardware isn't allowed by Apple's license.
